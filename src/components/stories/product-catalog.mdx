# Product catalog

Every control and pattern the DataSafeguard product (`idp-ui`) needs, mapped to the one component that does the job in this design system.

The mapping carries **behavior only**: what a control does, such as submitting a request, versioning a consent form, filtering a queue or uploading evidence. Nothing visual comes from the product. There are no product screenshots, class names or colors here, and none were copied into the components.

## Why one system

Today the product styles the same screens with Tailwind and Ant Design at once, and adds another library for jobs Ant Design already covers: a second select, a second date picker, a second table and pagination, and Chart.js next to Recharts. The same behavior (a button, an empty state, a modal, a filter) looks different from one screen to the next.

Here each behavior has one component. There is one radius scale, one type scale and one status treatment: `Badge` and `Alert`, nothing else. Tokens come from `src/styles/theme.css` only.

## How to read the tables

Rows are grouped by kind. A **primitive** is one control in `src/components/ui`. A **compound** is a pattern built from primitives.

- **Here**: what to import in this repo.
- **Story**: where to see it working, in light, dark and right-to-left.
- **In idp-ui**: where the behavior lives in the product today, so every row can be traced back.

## New in this pass

The product had these behaviors and the design system did not. Each is built from existing primitives and tokens, with no new dependency.

### File upload

Primitive · `FileUpload` from `@/components/ui/file-upload` · [Patterns/File upload](?path=/story/patterns-file-upload--evidence-upload)

A drop zone with a browse button on a native file input. It takes `accept`, `multiple` and `maxSize`, and lists each file with its size, upload progress, a reason when it is rejected or fails, and a remove button. It works from the keyboard, and focus stays in the list after a remove. Inside `FormControl` it picks up the label and the error.

In idp-ui: assessment attachments (`components/PIA_V2/UploadFile.jsx`), request evidence (`components/DSAR details/AttachmentTab.jsx`), the redaction source file (`components/SelectSource/Individual_Files.js`) and identity documents (`components/submitDsar/commonComponents/uploadImage.jsx`).

### Stepper

Primitive · `Stepper` from `@/components/ui/stepper` · [Patterns/Stepper](?path=/story/patterns-stepper--request-intake)

Horizontal steps that are complete, current or upcoming, with an optional description. The current step has `aria-current="step"`. With `onStepClick`, completed steps become buttons so people can go back. Later steps can never be skipped to.

In idp-ui: the cookie banner builder (`components/DCBConsole/CreateBanner/Layout.jsx`), the assessment template builder (`components/PIATemplateBuilder/NavigationTabs.jsx`) and product installation (`components/ProductInstallation/Installation/WorkflowSteps.js`).

### Version history

Compound · `VersionHistory` from `@/components/version-history` · [Patterns/Version history](?path=/story/patterns-version-history--consent-versions)

Saved versions of a record, newest first, each with its label, author, time and status: draft, published or active, shown as a `Badge`. Each row has a menu with View, Download and Restore; Restore is not offered on the active version. It has loading, empty and read-only states and fits in a panel or a `Sheet`.

In idp-ui: `components/common/VersionHistorySidebar.jsx`, used by consent lists (`components/ConsentsConfig/ConsentDetailPage.jsx`) and cookie banners (`components/DCBConsole/CreateBanner/CreateBanner.jsx`).

## Composed, not new

Filter bars, confirmations and create/edit sheets already exist as behavior, so there is no new `FilterBar`, `Confirm` or `FormSheet` component. The pattern stories compose `Input`, `Select`, `DatePicker`, `ConfirmDialog`, `Sheet` and `Form` instead.
